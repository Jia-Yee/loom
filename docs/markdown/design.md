# Loom 前端重设计方案

> 参考 https://github.com/cv936669367/ml_flow_design 的设计理念，结合 Loom 现有架构，设计三栏式可视化流程编辑器。

## 一、整体布局

```
┌─────────────────────────────────────────────────────────────┐
│  顶栏：Logo · 标签切换(控制台/流程编辑器/AI对话/代码) · 状态  │
├──────────┬──────────────────────────────────┬───────────────┤
│          │                                  │               │
│  左栏    │         中间画布                  │   右栏        │
│  节点库  │     (拖拽节点 + 连线)             │  参数配置     │
│          │                                  │               │
│  · 数据  │  ┌──────┐    ┌──────┐            │  节点信息     │
│  · 模型  │  │数据集│───→│ 切分 │            │  参数表单     │
│  · 分析  │  └──────┘    └──┬───┘            │  对应代码     │
│  · 评估  │                  ↓               │               │
│          │  ┌──────┐    ┌──────┐            │               │
│          │  │ LLM  │    │ 模型 │            │               │
│          │  │ 分析 │    │ 训练 │            │               │
│          │  └──────┘    └──────┘            │               │
│          │                                  │               │
├──────────┴──────────────────────────────────┴───────────────┤
│  底栏：执行日志（实时进度 + LLM 状态）                       │
└─────────────────────────────────────────────────────────────┘
```

## 二、左栏：节点库（可拖拽）

### 节点分类

```
📥 数据
   ├── 内置数据集 (diabetes, breast_cancer, california_housing)
   ├── CSV 上传
   └── 数据分析 (预览 + 统计 + 相关性)

🔧 处理
   ├── 数据切分 (test_size, seed, 分层)
   └── 特征工程 (预留)

🧠 模型
   ├── 线性回归 (linear_regression)
   ├── 随机森林 (random_forest)
   ├── Ridge 回归 (ridge)
   ├── 逻辑回归 (logistic_regression)
   └── + 自定义 (从注册表动态加载)

⚡ 搜索
   └── 超参搜索 (RandomizedSearchCV)

📊 评估
   ├── 回归指标 (MSE, R²)
   ├── 分类指标 (accuracy, f1, auc)
   └── 模型对比 (select_best)

🤖 LLM
   ├── 训练前分析 (数据集摘要 → LLM)
   ├── 训练后解读 (指标 → LLM)
   └── LLM 配置 (provider, model, api_key)

💾 输出
   ├── 结果持久化 (SQLite)
   └── 下载 (nodes.json, 完整结果)
```

### 交互

- 每个节点 `draggable=true`，拖到画布上生成节点实例
- 节点库从后端 `/api/models`、`/api/datasets` 动态加载
- 搜索框过滤节点
- 分类可折叠/展开

## 三、中间画布：流程编排

### 节点卡片

每个节点卡片包含：

```
┌─────────────────────────────┐
│ 📥 数据集: diabetes    [×]  │  ← 标题栏（可删除）
├─────────────────────────────┤
│ 输入端口          输出端口   │  ← 连接点
│  ● data    →    data ●     │
├─────────────────────────────┤
│ 442 样本 × 10 特征          │  ← 展示区
│ bmi, s5, bp...              │
├─────────────────────────────┤
│ ⏱ 0.3s    ✅ success        │  ← 状态栏
└─────────────────────────────┘
```

### 连线

- 从输出端口拖到输入端口创建连线
- SVG 贝塞尔曲线
- 连线有方向箭头
- 可点击连线删除

### 分支支持

```
         ┌→ model_A → metric_A ┐
dataset → └→ model_B → metric_B ┘→ comparison
         └→ LLM 分析（独立分支）
```

- 数据集分析可以作为独立分支：dataset → 数据分析节点（不参与训练流程）
- 多模型并行：从 split 节点分出多条线到不同 model 节点
- LLM 分析可以挂在任意位置：dataset → LLM_pre（独立分支），metric → LLM_post

### 画布操作

- 拖拽节点移动位置
- 滚轮缩放画布
- 拖拽空白处平移画布
- 双击节点展开详情
- 右键节点菜单（删除、复制、查看代码）
- 工具栏：运行、清空、自动布局、重置缩放

## 四、右栏：参数配置面板

选中节点后显示三部分：

### 4.1 节点信息

```
节点 ID: dataset-diabetes
节点类型: dataset
状态: ✅ success
```

### 4.2 参数表单（按节点类型动态生成）

| 节点类型 | 参数 |
|---------|------|
| dataset | 选择数据集名、查看预览 |
| split | test_size (滑块 0.1-0.5)、seed (数字)、stratify (开关) |
| model | 选择模型名、查看参数 |
| search | n_iter (数字)、cv (数字) |
| llm_analysis | provider (下拉)、model (输入)、api_key (密码框)、timeout (数字) |
| comparison | 选择排序指标 |

### 4.3 对应代码

```
┌─────────────────────────────┐
│  对应代码  [查看] [编辑]    │
├─────────────────────────────┤
│  # models/linear.py         │
│  @register_model("linear")  │
│  class LinearRegression...  │
│                             │
│  (可编辑，保存后热加载)      │
└─────────────────────────────┘
```

- 点击「查看」显示对应源码（只读模式）
- 点击「编辑」进入编辑模式，可修改代码
- 保存后热加载自动重启
- 不同节点类型显示不同代码文件：
  - dataset 节点 → `datasets/*.py`
  - model 节点 → `models/*.py`
  - split 节点 → `core/runner.py`（split 部分）
  - llm 节点 → `core/llm_analyzer.py`

## 六、分支场景示例

### 场景 1：数据集独立分析分支

```
dataset ──→ 数据分析（预览+统计+相关性）    ← 独立分支，不参与训练
       └──→ split → model → metric → llm_post
```

### 场景 2：多模型对比

```
dataset → split ──→ model_A (linear) → metric_A ──→ comparison
              └──→ model_B (forest)  → metric_B ──┘
              └──→ model_C (ridge)   → metric_C ──┘
```

### 场景 3：LLM 分析独立分支

```
dataset ──→ llm_pre（数据分析）         ← 独立分支
       └──→ split → model → metric ──→ llm_post（结果解读）
```

### 场景 4：超参搜索分支

```
dataset → split → model_A → search_A → metric_A
              → model_B → (跳过搜索) → metric_B
```

## 七、数据流

```
用户拖拽节点 → 画布状态 (nodes + edges)
     ↓
用户点击「运行」
     ↓
前端将 nodes + edges 发给后端 /api/run_stream
     ↓
后端按拓扑排序执行，SSE 实时推送每步状态
     ↓
前端更新节点状态 + 日志 + 画布渲染
     ↓
完成后保存到 SQLite，可历史回看
```

## 八、技术选型

| 部分 | 方案 | 说明 |
|------|------|------|
| 画布渲染 | 原生 DOM + SVG | 轻量，无框架依赖 |
| 拖拽 | HTML5 Drag API | 原生支持 |
| 连线 | SVG path | 贝塞尔曲线 |
| 参数表单 | 动态生成 | 按节点 type 映射表单字段 |
| 代码编辑 | textarea | 简单可用，后续可换 CodeMirror |
| 实时进度 | SSE (EventSource) | 已实现 |
| 状态管理 | 全局 JS 对象 | 无需 Vuex/Pinia |

## 九、与现有系统的关系

| 现有功能 | 新设计中的位置 |
|---------|---------------|
| 控制台（配置 + 画布 + 日志） | 流程编辑器（左栏 + 画布 + 右栏 + 底栏） |
| AI 对话 | 顶栏标签保留 |
| 代码查看编辑 | 右栏「对应代码」面板 |
| 历史记录 | 顶栏按钮保留 |
| LLM 配置 | 节点库「LLM」分类下的节点 |
| CSV 上传 | 节点库「数据」分类下的节点 |

## 十、实施计划

1. **Phase 1**：节点库 + 画布拖拽 + 节点渲染
2. **Phase 2**：连线 + 参数配置面板
3. **Phase 3**：代码查看面板 + 运行按钮
4. **Phase 4**：分支支持 + 数据分析节点
5. **Phase 5**：历史回看 + 保存/加载流程
